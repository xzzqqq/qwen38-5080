## Runner 数值验收

命令：

```bash
make m2-numeric
```

三条真实 prompt 固定 greedy 16 步，teacher forcing；每条都检查：

| 检查 | 数量（每 prompt） | 结果 |
|---|---|---|
| NVFP4Linear vs 同 A/W 量化 dequant reference | 6800 | **0 failures**；worst nrmse **0.00359**、cos 0.9999975、max_rel 0.00384 |
| activation quant 参考 vs FlashInfer | 6800 | 诊断项；worst nrmse 0.0587、cos 0.99836、max_rel 0.20 |
| GDN chunk/recurrent vs FP32 recurrence | 816 | **0 failures**；worst nrmse 0.00398、max_abs 0.0078125、max_rel 0.00758 |
| GDN final state vs FP32 recurrence | 816 | **0 failures**；worst nrmse 2.48e-5、max_abs 3.65e-5 |
| lm_head dequant reference（每一步） | 16 | **0 failures**；worst nrmse 0.0016716、max_abs 0.1071、max_rel 0.00323 |
| hidden states | 3×17 | 全部 finite，BF16 |
| cache | 3 | KV BF16、recurrent FP32、conv BF16；长度正确 |

容差：

- NVFP4Linear：`nrmse ≤ 5e-3`、`cosine ≥ 0.99999`、`max_rel ≤ 1e-2`；
- GDN：`nrmse ≤ 5e-3`、`cosine ≥ 0.9999`、`max_rel ≤ 1e-2`；
- lm_head：同 NVFP4Linear；
- activation quant：诊断项，不参与退出判定。FlashInfer 与 PyTorch E2M1/E4M3
  rounding 在真实 activation 上有少量 code 不同，worst 超过参考容差是预期现象。

说明：NVFP4 的 reference 用与目标相同的 FlashInfer A/W 量化结果做 dequant，
验证权重 layout、scale 和 GEMM；decode 每一步都执行 NVFP4/GDN 对拍，每一步
logits 都用 lm_head dequant reference 检查。hidden/cache 只做 finite/dtype/length
结构检查，不做跨 chunk/recurrent kernel 的 bitwise hidden 对拍（两条 kernel 路径
的 reduction 不同，不能作为正确性判据）。

## 容量与显存

命令：

```bash
.venv/bin/python scripts/m2_capacity.py --depths 512,7680
```

| depth | cache_len | prefill | decode 512 | load end/peak | prefill peak | decode peak | reserved | free |
|---|---|---|---|---|---|---|---|---|
| 512 | 1023 / 1023 | 0.700 s | 43.894 s（11.64 tok/s） | 14.457 / 14.457 | 14.776 GB | 14.775 GB | 14.915 GB | 1.357 GB |
| 7680 | 8191 / 8191 | 6.574 s | 44.007 s（11.61 tok/s） | 14.457 / 14.457 | **15.620 GB** | **15.423 GB** | **15.859 GB** | **0.413 GB** |

- peak 按 phase 分别 reset：load / prefill / decode 不再互相包含；
- 512 和 7680 都 `ok=true`：finite、cache 长度、KV BF16、recurrent FP32、conv BF16；
- 最后一步 token 不再次 forward，所以 `cache_len = depth + 512 - 1`；
- 8K 的峰值在 **prefill 15.620 GB**，decode 回落到 15.423 GB；
- loader 直接读 packed checkpoint，没有单独的 repack 峰值；
- 8K baseline 只剩 **0.413 GB** free，DFlash2 容量会更紧。

## 已知限制

- 没有整份 BF16 reference model；数值 reference 是逐 op/逐层运行。
- activation quant 的 PyTorch reference 与 FlashInfer 有少量 rounding 差异，
  只作诊断；NVFP4Linear 本身用相同 A/W 量化验证。
- GDN prefill 和 decode 都做了 FP32 recurrence 对拍；hidden/cache 只做
  finite/dtype/length 结构检查，不做跨 chunk/recurrent kernel 的 bitwise 对拍。
- ShapeStableLinear 的 padding、GDN/conv fallback 和 lm_head 大 vocab 仍是 M3
  性能优化对象；M2 只冻结正确性。

## M3 交接

- `EagerTextRunner` 可直接作为正确性 reference；static cache / CUDA Graph 从
  同一权重和 cache 布局开始。
- 需要处理：Python chunk/decode loop、DynamicCache 变长、HostEmbedding 的
  CPU gather + H2D、ShapeStableLinear 分块/补 zero、lm_head 大 vocab、
  `causal_conv1d` / `fla` fallback。
- M3 先做 static cache，再录 graph；性能 baseline 必须与 M2 的 eager 输出对拍。
